# RB-01 · Fundação

Branch: `feature/rb-01-fundacao` · Referência: SPEC §7, §9, §10 (tarefa 01), §5 (Entrada/Menu e foco), §12.

## Objetivo observável
Um checkout limpo gera, com comandos versionados, um `RotaBrava.exe` para Windows que abre numa janela, mostra um menu com foco inicial, aceita entrada (teclado, mouse, controle) e fecha corretamente.

## Escopo
- Toolchain fixada e reproduzível (`tools/toolchain.json`, `tools/setup-toolchain.ps1`).
- Projeto Godot em `game/`: renderizador Mobile, Input Map com intenções, perfil `Windows Desktop`.
- Cena inicial: menu com `Jogar`, `Opções`, `Sair`; tela de "jogo" mínima (placeholder) com `Voltar`.
- Ajudantes: `tools/godot.ps1`, `tools/build-windows.ps1`, `tools/smoke-test.ps1`.
- Fora do escopo: episódio, arte, áudio, save, opções funcionais, toque (RB-02+).

## Contrato de interação
| Intenção (Input Map) | Teclado | Controle | Mouse/toque |
|---|---|---|---|
| `move_left/right/up/down` | A/D/W/S, setas | analógico esq. | — |
| `interact` | E | botão primário (A) | — |
| `pause` (voltar/pausar) | Esc | Start | — |
| `ui_accept`, `ui_cancel`, navegação | padrão Godot | padrão Godot | clique |

- Ao abrir o menu, `Jogar` tem foco. Cima/baixo move o foco; `ui_accept` ou clique ativa.
- `Jogar` abre a tela de jogo (placeholder). Nela `interact` incrementa um contador visível e `pause`/`Voltar` retorna ao menu com foco recuperado em `Jogar`.
- `Sair` fecha o processo com código 0. `Esc` no menu principal não fecha o jogo.
- `Opções` abre painel placeholder com `Voltar`; `ui_cancel` volta e devolve foco em `Opções`.

## Critérios de aceite
1. `tools/setup-toolchain.ps1` instala a Godot fixada (hash conferido) sem tocar fora de `.tools/`.
2. Importação limpa (`--import`, sem `game/.godot`) termina com código 0 e sem erros de script.
3. `tools/build-windows.ps1` gera `build/windows/RotaBrava.exe` + `.pck` (ou embutido) com código 0.
4. Teste determinístico (`game/tests/`) verifica Input Map, foco inicial e navegação menu → jogo → menu, e passa com código 0 (headless).
5. O `.exe` exportado abre uma janela com renderização real, e `smoke-test.ps1` o inicia, confirma processo vivo e janela por alguns segundos, e o encerra; captura de tela guardada em `captures/`.
6. Renderizador efetivo é Mobile (registrar linha de log do `--verbose`/`OS`).
7. Nada de build, cache `.godot`, `.tools` ou credenciais no Git.

## Casos de falha
- Hash divergente no download → script aborta e apaga o arquivo.
- Template ausente → `build-windows.ps1` falha com mensagem clara (não gera exe parcial).
- Ação ausente do Input Map → teste falha nomeando a ação.
- Exportar com saída em `build/` inexistente → script cria o diretório.
